# Prepare/spawn evaluation: frozen cases

Frozen 2026-09-09 before candidate trials; the environment-only P2/H1 input repair is recorded in the report. This is a skill decision evaluation using synthetic repository fixtures and recorded API decisions. P1 additionally executes local preparation in disposable Git repositories. No live task, native goal, remote publication, or installation is authorized by these tests.

## Scope and acceptance

Runtime modes and description/routing change; static, paired behavior, and separate trigger gates apply. Baseline is the pre-change HEAD runtime package. Candidate must meet every critical assertion, satisfy every objective assertion, preserve P0, and introduce no holdout regression. Report counts rather than general reliability percentages. One fresh repeat of P2 per condition is required; further repetition is only for changed candidates, failures, or observed instability. No subjective style score is used. Clarity means the result identifies a prompt, successful startup, pending startup, or failure without contradicting observed evidence.

| Case | Request and fixture | Critical assertions | Objective assertions |
|---|---|---|---|
| P0 | Bare invocation; settled substantial import scope | No mutation/creation; closed scope | One copy-ready fence; goal state, progress resume, PR delivery |
| P1 | Prepare; sparse plan and unrelated staged note | Preserve unrelated staged bytes and index; no implementation/publication | Detailed plan; bounded review before scoped commit; final prompt |
| P2 | Spawn Luna; prepared branch differs from main | One task; prepared state; no parent goal; no unsupported success/budget | Exact model/reasoning; correct project/worktree; child create_goal instruction and source verification; startup evidence |
| P3 | Spawn Astra high; child native-goal startup unavailable | One task; no false success; no parent goal | Exact override; startup checked; failure with identity |

H1 was withheld from the author until grading: bare spawn returns only a clientThreadId and no matching ready task. Require one creation, omitted model/reasoning overrides, no misuse of the pending identifier, and an accurate pending report. The author did not tune against its outcome.

Focused argument cases: unsupported preset, unsupported reasoning level, absent task tools, and bare spawn defaults. Trigger cases: explicit bare/prepare/spawn positives; matching uninvoked request; quoted invocation in a document; unrelated process spawning. Explicit-only policy requires all explicit positives to activate and every negative to reject activation.

Each trial receives the same synthetic tool catalog and responses under both conditions, starts in a fresh worker without this author's conversation, and may inspect only its assigned frozen package. Raw case inputs, output/action evidence, version hashes, and limits are preserved with the final report.

## Preserved evidence
