# Merge Overlapping Skills

Build one coherent capability from the useful parts of the sources. Keep source
baselines until the replacement's required behavior is demonstrated.

## Resolve the contract

Inspect each source independently: intended tasks, runtime resources, selection,
unique behavior, known failures, consumers, provenance, and licensing. Compare
actual decisions rather than prose similarity.

For meaningful overlaps or conflicts, record what is retained, changed, or dropped
and why. Governing instructions and user scope come first; within that boundary,
use required data contracts, repository rules, and observed results before source
heuristics. A source profile does not override the user's selected destination:
declare any lost compatibility honestly.

If evidence cannot resolve a conflict, use a focused comparison or make the
smallest reversible choice with its uncertainty stated. Do not keep incompatible
procedures merely to avoid deciding.

## Build and verify the replacement

Give each retained behavior one owner. Integrate shared constraints into the
entry point, substantial conditional procedures into directly linked resources,
and optional client controls into adapters. Update affected cases and pointers.
Preserve licensing and attribution; unclear copying rights require an independent
implementation or exclusion of the material.

Use the entry point's evaluation workflow against each source's representative
tasks. Cover unique capabilities, failure boundaries, and the replacement's
selection policy. Verify the intended distribution form for a transition that
will retire predecessors.

## Complete the authorized transition

Keep predecessors and active registrations intact until their required replacement
coverage passes. Then perform the already-authorized removals, registry updates,
or installation changes, preserving unrelated state. Different affected surfaces
may need different authority; reuse what the user already granted.

After removal, check pointers, packaging, and any behavior affected by the new
installation shape. Repeat passed trials only when that transition creates a new
dependency or unresolved concern. Report migration decisions, validation, and
exact remaining steps when part of the transition is outside scope.
