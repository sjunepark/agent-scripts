+# Contributing to tally
+
+This guide is for maintainers. User-facing usage lives in the [README](README.md).
+
+## Development
+
+Install dev dependencies with `pip install -e .[dev]`. Run `make test` for the
+test suite and `make lint` for ruff. Tests live in `tests/` and mirror the
+module names in `src/`.
+
+## Code layout
+
+- `src/tally.py` holds the CLI entry point, config loading, and counting.
+- `scripts/bump_version.py` bumps `VERSION` during releases.
+- `docs/decisions/` holds accepted decision records; do not edit them.
+
+## Release process
+
+1. Make sure `make test` and `make lint` pass on `main`.
+2. Run `make release`, which bumps `VERSION` and tags `v<version>`.
+3. Push the tag; CI publishes to PyPI.
+4. Announce the release in the changelog discussion.
+
+## Current gaps
+
+These differ from the procedures above in the current tree:
+
+- There is no `pyproject.toml`, so `pip install -e .[dev]` does not work yet.
+- `scripts/bump_version.py` is a placeholder; `make release` currently tags the
+  existing `VERSION` without bumping it.
+- `tests/test_tally.py` contains only a placeholder test.
+- No CI configuration is checked in, so the PyPI publish step is not defined
+  in this repository.
